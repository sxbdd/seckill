# 决策记录（ADR / Decision Log）

> 用途：记录"为什么这么定"。冻结后变更必须新增 ADR，禁止悄悄改。
> 状态：ADR-001~010 已由用户 2026-09-08 确认默认；ADR-011~020 为架构决策，随设计评审可修订。

## ADR-001 用户产生方式：开放注册 + 预置 ADMIN
- 备选：仅预置账号（无注册）。选开放注册：需求真实、可演示完整链路；成本低（已有登录经验）。
- 风险：无手机/邮箱验证，仅教学级安全；登记 v2 增强。

## ADR-002 每人每活动限购 1 件
- 备选：限购 N 件。选 1：秒杀惯例，判重与库存模型最简单。若改 N 需重构判重为计数。

## ADR-003 待支付订单不自动取消（v1）
- 备选：延迟队列/定时任务自动取消。v1 不做：引入调度复杂度；登记 v2（M4+ 候选）。
- 已知限制：待支付订单可长期存在，占用库存直至手动取消。可接受（教学项目，无真实资金）。

## ADR-004 取消规则：待支付可取消；已支付不可取消
- v1 无退款；已支付取消等价退款流程，明确不做。

## ADR-005 支付用模拟接口（幂等）
- 真实支付需第三方/资质，不做。模拟支付仅改状态，必须幂等（重复调用成功且不重复生效）。

## ADR-006 库存粒度：每活动一份库存（无 SKU/多规格）
- 多规格需库存维度拆分与 sku 判重，复杂度翻倍，v1 不做。

## ADR-007 "重复抢购"精确语义：有未取消订单即已抢；已取消可再抢
- 影响：判重先查"是否存在未取消订单"，唯一索引 uk_user_activity 允许"已取消后重建"。
- 定案（2026-09-08）：判重以"存在未取消（status∈0,1）订单"为准；采用**生成列 active_key + 唯一索引 uk_user_active**（仅活跃订单参与唯一约束，取消后 active_key=NULL 自动释放名额），既保留 DB 级防重最后防线，又支持取消后重抢。详见 database-design.md §3.5。

## ADR-008 Redis 宕机降级：可配置开关，降级 DB 条件更新
- 不允许静默超卖；降级期间性能下降但正确性保持。
- 风险：降级开关切换是人工操作；登记 v2 自动熔断。

## ADR-009 管理端范围：创建 + 查看 + 手动重载库存
- 不做编辑/下线/删除：避免"已开抢活动被改"的一致性问题。

## ADR-010 同一商品多活动时间窗允许重叠（v1 不校验）
- 重叠由运营负责；强制禁止需区间重叠校验，价值低。

## ADR-011 技术栈：Spring Boot 3 + JDK17 + MyBatis-Plus + MySQL8 + Redis + Maven
- 备选：Spring Boot 2/JDK8（兼容旧环境）。选新版：LTS + 主流招聘要求。
- ORM 备选 JPA：选 MyBatis-Plus 因 SQL 可控、国内主流。
- 鉴权备选 Spring Security/JWT：v1 用自研 token(UUID+Redis)，轻量可解释；Security 学习成本高，登记 v2 可换 JWT。

## ADR-012 单体架构，不引入微服务/MQ/分库分表
- 业务理由：单机可复现目标问题（并发扣减/缓存/限流），微服务带来的分布式一致性复杂度对 v1 无收益。
- 演进路径：若流量扩大 → 前置拦截(CDN/静态化) → 水平扩容 → MQ 削峰 → 分库分表（登记 v2）。

## ADR-013 防超卖双方案：A=DB条件更新(对照/兜底)，B=Redis+Lua(最终)
- A 简单可靠作基线；B 提升吞吐。两者都需压测留档（验收标准 3）。

## ADR-014 一致性模型：Redis 为预扣账本(可丢可重建)，MySQL 为最终账本(不允许错)
- 对账以 DB 为准；任何不一致先记录告警，不自动改 DB。

## ADR-015 状态判定以时间为准，DB status 仅冗余
- 避免"状态字段与时间不同步"类 bug。

## ADR-016 订单号：时间戳(ms)+6位随机，唯一索引兜底
- 备选 Snowflake：单机无分布式需求，随机后缀足够；唯一索引+重试保证不重复。

## ADR-017 时间与时区：统一 Asia/Shanghai，DATETIME 本地时间
- 教训：LocalDateTime 用 UTC 转 epoch 会导致 ±8h 偏差（参考 anfemglan/seckill 的 bug），代码中禁止混用时区假设。

## ADR-018 缓存：Cache Aside + 空值缓存(穿透) + 互斥锁(击穿) + TTL 随机(雪崩)
- 商品详情缓存；库存**不缓存到业务读路径**（库存走 Redis 预扣账本，属写路径）。

## ADR-019 限流：单机 Guava 令牌桶
- 单实例部署下本地限流足够；分布式限流(Redis)待多实例时引入。说出边界比堆技术重要。

## ADR-020 文档体系：README + docs/*（7 份）
- 裁剪理由：单人本地项目；operations 并入 deployment；不建 CI/CD（无多环境）；上线前补齐项在 deployment.md 登记。


## ADR-021 代码结构取舍：service 用具体 @Service 类 + DTO 用 Java record
- 背景：architecture.md 原描述为 service + impl 分包。
- 决策：本项目中 service 均为单一职责、单实现，故采用具体 @Service 类（省略空接口层）；DTO 采用 Java 17 record 减少样板。
- 理由：单人项目，避免无意义的接口间接层；record 不可变、适合传输对象。
- 风险：未来若出现多实现/多团队，再按需抽接口。
- 文档同步：architecture.md §3 包结构已同步更新。
