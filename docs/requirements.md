# 需求规格说明书（Requirements）

> 状态：v1.0 冻结（2026-09-08，用户确认 10 项默认决策，见 decisions.md ADR-001~010）
> 唯一事实来源链：本文件定义"做什么"，technical-design/database-design/api 定义"怎么做"。

## 1. 项目定位
电商**限时限量低价抢购**（秒杀）后端服务：商品在固定时间窗内限量特价，开抢瞬间大量用户并发点击"立即抢购"。
核心目标：**不超卖、不重复抢、不被瞬时流量打垮**。

## 2. 用户与角色
| 角色 | 说明 | 权限 |
|---|---|---|
| 游客 | 未登录 | 浏览商品/活动 |
| 用户 USER | 注册登录后 | 秒杀下单、查/取消/模拟支付自己的订单 |
| 运营 ADMIN | 预置管理员账号 | 创建活动、查看全部活动、手动重载 Redis 库存 |

## 3. 使用场景
- S1：活动开抢瞬间，大量用户同时点"立即抢购"（核心场景，并发验证目标）；
- S2：用户浏览进行中/即将开始的活动，查看倒计时与有货状态；
- S3：运营在活动开始前创建活动并设置库存；
- S4：用户查看/取消自己的订单；取消后库存回补；
- S5：用户对订单执行模拟支付（幂等）。

## 4. 功能需求
### F1 用户
- F1.1 注册：username 唯一（4~50 位），密码 ≥8 位 BCrypt 存储，默认角色 USER；
- F1.2 登录：校验通过签发 token（TTL 2h，存 Redis），失败统一提示；
- F1.3 登出：删除服务端 token；
- F1.4 身份识别：业务接口一律从 token 取 userId，禁止信任客户端传参。
### F2 商品
- F2.1 商品详情（缓存）；F2.2 商品列表（分页，仅上架）；数据由初始化脚本预置。
### F3 秒杀活动（ADMIN 创建）
- F3.1 创建入参：goodsId、seckillPrice、startTime、endTime、stock；
- F3.2 校验：price>0；stock ∈ [1,100000]；endTime>startTime；startTime≥now-容忍误差；商品存在且上架；
- F3.3 创建即：落库（活动+独立库存）并预热 Redis（同一次请求完成，事务+补偿）；
- F3.4 用户侧列表：进行中+即将开始，分页；详情含倒计时、有货/售罄布尔，**不暴露精确剩余库存**；
- F3.5 管理侧：全量查看。
- 状态推导：以时间判定（未开始/进行中/已结束），DB status 仅冗余展示。
### F4 秒杀下单（核心）
流程：鉴权 → 活动存在且进行中 → 幂等判重 → 原子扣库存 → 生成订单（同事务）→ 返回 orderNo。
业务规则：
- R1 仅 `now ∈ [start_time,end_time)` 且活动存在时放行；
- R2 同一用户同一活动最多一笔**未取消**订单；已取消后可再抢（库存允许时）；每人限 1 件；
- R3 库存扣减必须原子，任何路径不得扣成负数；
- R4 扣库存与生成订单同生共死（同一事务/等效保证）；
- R5 订单金额以秒杀价为快照；
- R7 所有外部输入参数校验。
异常映射：1003 不存在 / 1001 未开始 / 1002 已结束 / 2001 已抢完 / 2002 重复抢购。
### F5 订单
- F5.1 我的订单（分页，仅本人）；F5.2 详情（仅本人）；
- F5.3 取消：仅"待支付"可取消；取消后库存回补（先 DB 后 Redis，对账收敛）；重复取消幂等返回成功；已支付取消→400；
- F5.4 模拟支付：待支付→已支付，幂等；已取消→400。
- 边界（v1 明确不做）：**不自动取消超时未支付订单**（登记 v2）；不做真实支付/退款。
### F6 对账（M3 交付）
每分钟定时任务：对比进行中/未开始活动的 Redis 库存与 DB 库存；不一致时**以 DB 为准重置 Redis** 并告警日志。
### F7 限流（M4 交付）
单机令牌桶（默认 2000 QPS 可配置）作用于 `/api/seckill/**` 下单路径；超限 429。

## 5. 数据变化（每个功能写什么表）
| 功能 | 读 | 写 |
|---|---|---|
| 注册 | t_user(username 查重) | t_user insert |
| 登录 | t_user | Redis user:token |
| 创建活动 | t_goods | t_seckill_activity + t_seckill_stock + Redis 预热 |
| 秒杀下单 | t_seckill_activity(+Redis) | t_seckill_stock -1 + t_seckill_order insert + Redis 判重/扣减 |
| 取消订单 | t_seckill_order | status=2 + t_seckill_stock +1 + Redis INCR |
| 模拟支付 | t_seckill_order | status=1 + pay_time |
| 对账 | 两者 | Redis 重置（以 DB 为准） |

## 6. 验收标准（成功标准）
1. 500 并发压测后：订单总数 == 活动初始库存，无超卖、无重复；
2. 核心下单 P95 ≤ 200ms（本机参考，以实测为准）；
3. 方案A(DB) vs 方案B(Redis+Lua) 压测对比留档；
4. 集成测试覆盖 11.1 用例矩阵且全绿。
