# 测试策略说明书（Testing）

## 1. 测试分层（按项目规模裁剪）
| 层 | 工具 | 覆盖目标 |
|---|---|---|
| 单元/服务测试 | JUnit5 + Mockito | Service 规则与状态机 |
| 接口集成测试 | MockMvc + 真实 MySQL/Redis | 全链路与错误码 |
| 并发/性能测试 | JMeter（脚本入库） | 验收标准 1/2/3 |

## 2. 接口用例矩阵（必须全绿）
| # | 用例 | 期望 |
|---|---|---|
| T1 | 注册成功 / 重名 / 弱密码 | 200 / 400 |
| T2 | 登录成功 / 密码错 | 200 / 400 |

| T6 | 用户 A 下单→取消→再下单 | 第二次 200（若库存允许）；仅 1 笔活跃订单 |

| T8 | 活动开始前 / 结束后下单 | 1001 / 1002 |
| T9 | 不存在活动下单 | 1003 |

| T11 | 重复取消 | 200（幂等） |
| T12 | 已支付订单取消 | 400 |
| T13 | 模拟支付成功 / 重复支付 | status=1；重复调用 200 不重复生效 |
| T14 | 已取消订单支付 | 400 |
| T15 | 用户查他人订单 | 403 |

## 3. 并发测试
- 同活动 500 并发下单（JMeter）：断言 订单数 == 初始库存；无 2002 之外的异常；DB 剩余库存 + 订单数 == 初始库存；
- 结果写入压测报告（模板见下）。

## 4. 压测报告模板（交付物）
```
环境: CPU / 内存 / OS / JDK / MySQL版本 / Redis版本
场景: 线程数=500, 持续时间=N s, 接口=POST /api/seckill/{aid}/orders
结果: 总请求 / 成功 / 2001 / 2002 / 5xx / 错误率 / TPS / P95(ms)
对比: 方案A(DB条件更新) vs 方案B(Redis+Lua)
库存核对: 初始库存 - DB剩余 == 订单数(活跃)  ✓/✗
```

## 5. 验收与回归
- 每个里程碑跑对应子集；M5 全量回归；
- 文档/代码变更后跑受影响用例（第 13 节变更流程要求）。
